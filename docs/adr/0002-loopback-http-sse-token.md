# ADR-0002：前后端通信：本机 HTTP（REST + SSE）+ 启动令牌

- 状态：已采纳
- 日期：2026-11-24

## 背景

React 前端需要调用 Java 后端：普通请求（会话列表、配置、审批决定）和服务端推送（模型逐字输出、工具调用、审批请求、错误）。项目定位为企业级产品。

## 决定

1. Java 后端以 HTTP 服务运行，**只监听 `127.0.0.1`**，端口由 Rust 每次随机分配；
2. 普通请求用 **REST**，流式推送用 **SSE**（`POST /api/agent/stream` 返回 `text/event-stream`）；
3. Rust 每次启动生成 **随机令牌**，通过环境变量 `LIHARNESS_TOKEN` 传给 Java，通过 Tauri command 交给前端；Java 对所有 `/api/**` 接口（包括健康检查）校验 `Authorization: Bearer <令牌>`；
4. 前端使用 **Tauri HTTP 插件** 发请求（请求由 Rust 发出，不受浏览器跨域限制），因此后端**不开放 CORS**；
5. 令牌**不写入**运行记录、日志、配置文件和前端持久化存储；
6. 接口层与传输方式解耦：控制器只做协议转换，业务都在内核服务里，必要时可增加 stdio 传输。

## 备选方案

| 方案 | 不选的原因 |
|---|---|
| stdio JSON-RPC（Rust 转发） | 更封闭、无端口；但只能服务一个父进程，调试和测试工具少，每个新接口都要在 Rust 里写转发 |
| WebSocket | 双向能力超出需求；SSE + REST 更简单，代理与日志工具支持更好 |
| gRPC | WebView 中需要 grpc-web 代理，复杂度高 |
| 不加令牌 | 本机任何程序、浏览器中的恶意页面都可能调用后端执行命令，**不可接受** |

## 后果

好的：
- 标准协议：鉴权、日志、链路追踪、OpenAPI 契约、接口测试与压测工具都现成
- 同一后端可服务桌面窗口、CLI、IDE 插件，将来可演进为团队服务（届时把令牌换成企业 SSO）
- 在 WebView 开发者工具里能直接看到请求与事件流，排查方便

坏的：
- 占用一个本机端口；部分企业终端安全软件可能对监听端口告警（已限制为回环地址）
- 端口由 Rust 分配后释放再交给 Java，存在极短的竞争窗口，需要失败重试
