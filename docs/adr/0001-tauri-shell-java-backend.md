# ADR-0001：桌面形态：Tauri 2 外壳 + Java 后端子进程

- 状态：已采纳
- 日期：2026-11-24

## 背景

LiHarness 要做成桌面应用，智能体内核用 Java 实现，界面希望使用 React + TypeScript 生态（流式 Markdown、代码高亮、时序图、审批卡片）。同时需要原生能力：进程管理、目录选择、系统通知、Git 状态。

## 决定

- 桌面外壳使用 **Tauri 2**，前端 **React 19 + TypeScript + Vite**；
- Java 后端作为 **独立子进程** 运行，由 Tauri 的 Rust 层负责启动、健康检查和终止；
- 智能体逻辑全部在 Java，Rust 只做进程管家与本机能力，**不写任何智能体逻辑**。

## 备选方案

| 方案 | 不选的原因 |
|---|---|
| Electron + Java | 多一个 Node 运行时，安装包大；与 Tauri 相比没有实质收益 |
| JavaFX / Compose Desktop | 单进程单语言，但放弃 React 生态，界面要用另一套技术重做 |
| 纯 Web（浏览器访问本地服务） | 没有原生能力；用户需要自己启动后端。我们的接口保持 Web 兼容，将来可以同时支持 |

## 后果

好的：
- 智能体能力只实现一次，桌面、Web、CLI 共用同一后端
- 前端没有命令执行面，安全边界清晰
- 安装包体积小于 Electron

坏的：
- 涉及三种语言（Java、TypeScript、少量 Rust）
- 需要打包 Java 运行时（jlink 精简 JRE），安装包比纯 Tauri 应用大几十 MB
- Java 冷启动 2–4 秒，界面需要“后端启动中”状态
- 多一个进程，需要认真处理生命周期（见 ADR-0005）
