# ADR-0005：Rust 进程管家：端口、运行记录、遗留进程回收、优雅退出

- 状态：已采纳
- 日期：2026-11-24

## 背景

Java 后端是一个独立子进程，并持有 H2 文件库的锁。如果应用异常退出（崩溃、强制结束），遗留的 Java 进程会继续占用端口和数据库文件，导致下次启动失败。

## 决定

Rust 层承担完整的进程生命周期：

1. **启动前回收**：读取 `<应用数据目录>/runtime/backend.json`；若记录中的 PID 仍存活，且其命令行包含记录中的 jar 路径，则终止它；然后删除记录。
2. **分配端口**：`TcpListener::bind("127.0.0.1:0")` 取得空闲端口后释放，交给 Java；Java 启动失败时换端口重试（最多 3 次）。
3. **生成令牌**：每次启动随机生成，通过环境变量传递，不落盘。
4. **启动参数**：`--spring.profiles.active=standalone --server.address=127.0.0.1 --server.port=<端口> --liharness.data-dir=<应用数据目录>`；环境变量 `LIHARNESS_TOKEN`、`LIHARNESS_PARENT_PID`；stdout / stderr 重定向到日志文件。
5. **运行记录**：启动成功后原子写入 `{pid, port, jarPath, startedAt}`（先写临时文件再 rename），**不含令牌**。
6. **就绪判断**：轮询 `GET /api/health`，最多 60 秒。
7. **优雅退出**：应用退出时调用 `POST /api/admin/shutdown`，等待最多 5 秒；超时则终止**我们自己启动的那个子进程**；最后删除运行记录。
8. **双保险**：Java 端父进程看门狗，发现 Tauri 进程已不存在时自行退出。

## 备选方案

- **由 Java 自己绑定端口 0 再把端口打印到 stdout**：没有竞争窗口，但需要解析 stdout；而我们希望 stdout 直接重定向到日志文件。
- **不做遗留进程回收**：异常退出后用户需要手动结束 Java 进程，体验不可接受。
- **只按 PID 回收**：PID 会被系统复用，可能误杀无关进程，不安全。

## 后果

- 异常退出后再次启动可以自动恢复
- 读取进程命令行依赖系统命令（`ps` / PowerShell），需要在各平台分别验证
- Windows 与 macOS / Linux 的终止方式不同，需要分别测试
